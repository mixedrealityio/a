# GLB Viewer for Apple Vision Pro

Loads a binary glTF (`.glb`), shows it as a volume (or at real size in your room), and lets you work
with its **product structure**: enlarge it, slice it, explode it, and remove any subtree or all parts.

> **Status:** written without access to Xcode, so the Swift sources have **not been compiled or run**.
> What *was* checked: the sample GLB's format and winding, and the slicing algorithm (ported to Python).
> Expect to fix a few compile errors on first build — see "Verification" below.

## Build

Requires Xcode 16+ (visionOS 2 SDK) and [XcodeGen](https://github.com/yonaskolb/XcodeGen).

```sh
brew install xcodegen
python3 Tools/make_sample_glb.py      # only needed if Samples/GearboxAssembly.glb is missing
xcodegen generate
open GLBViewer.xcodeproj
```

Set your team under *Signing & Capabilities*, then run on the Apple Vision Pro simulator or a device.

## Using it

| Goal | How |
|---|---|
| Load a model | **Open GLB…** (Files) or **Load Sample** |
| Select a subtree | Tap a part in the model, or pick a row in *Product structure*. **Parent** moves up one level |
| Remove a subtree | Select it → **Remove**. The eye icon on a row toggles one node. **Restore** brings it back |
| Isolate a subtree | Select it → **Isolate** (hides everything else) |
| Remove / restore all parts | **Remove all parts** / **Restore all** |
| Enlarge | Pinch the model, use the *Size* slider, **Real size**, or **In my room** (full-size immersive view) |
| Turn | Drag sideways on the model |
| Exploded view | *Exploded view* slider. Scope **Whole model** or **Selection** (explodes only the selected subtree) |
| Slice | *Slice* → pick axis, drag the plane, optionally **Keep the other side** |

## How it works

```
Sources/GLBViewer
├── GLTF/GLTFSchema.swift     Codable subset of the glTF 2.0 JSON
├── GLTF/GLBLoader.swift      GLB chunks → accessors → ProductNode tree + materials
├── Model/ProductNode.swift   The product structure (assemblies/parts) and per-part triangle data
├── Model/ExplodeLayout.swift Per-level radial displacement, relative to the parent
├── Model/MeshClipper.swift   Triangle/plane clipping (Sutherland–Hodgman), edge-shared cut vertices
├── Model/ViewerModel.swift   Scene graph, selection, visibility, scale, explode, slice
├── Scene/SceneBuilder.swift  ProductNode tree → RealityKit entities, PBR materials, textures
└── UI/                       Control panel, tree, volumetric + immersive model views
```

* **No glTF library.** RealityKit cannot read GLB natively, so the loader parses it directly.
* **Product structure = the glTF node tree.** A node with children is an assembly, a node with a mesh is a part.
  Naming comes from the node's `name`; give your CAD export meaningful node names.
* **Exploded view** moves each child away from the centre of its parent in proportion to how far it already
  sits from it. Offsets are relative to the parent entity, so sub-assemblies move as a unit and spread on top.
* **Slicing** clips the triangle data on the CPU in model space and swaps the entity's mesh, debounced while
  dragging. (RealityKit on visionOS has no clip-plane render state and `CustomMaterial` is unavailable.)

## Known limitations

* **Slices are open.** Cut surfaces are not capped, so you see into hollow parts. Capping needs loop
  extraction + triangulation per part.
* Slicing is computed on the assembled pose; combining it with an exploded view clips the un-exploded geometry.
* Not supported: Draco / Meshopt-compressed meshes (the loader says so), sparse accessors, animation, morph
  targets, skinning (shown in bind pose), external `.bin` files (use `.glb`), KTX2/Basis textures.
  Only `TEXCOORD_0` and the base-colour texture are used.
* Large models (hundreds of thousands of triangles) re-slice slowly because meshes are regenerated.
